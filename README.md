# NewGameLaunchSchedule

新玩法上架节奏预估 Demo：在「上太多相互倾轧、上太少玩家玩不到想玩的」之间，求解**每周三上新专区该上几个、上哪些玩法**。

纯静态页面，无构建、无依赖，`index.html` 直接打开即可运行。

## 业务场景

- 有一个「上新专区」，**每周三 10:00** 一次性同时上架 X 个玩法；
- 每批在专区**持续曝光 14 天**，超过 14 天退池；
- 因此任意时刻在池 = **本周批 + 上周批**（两批重叠 7 天），专区槽位同时被 2X 个玩法占用 → 单批上限 = ⌊槽位 / 2⌋；
- 每个玩法都可设定**「整个周期内的累计新进玩家数」上限**（可触达人群 / 承接预算），累计触顶后曝光照旧占据专区，但不再转化为新进；
- 每个待上架玩法还要回答一件事：**这个周期到底能不能完成获客目标**——这需要看它的人群名单有多大、和大盘 / 存量 / 同批玩法重叠多少，而不只是看曝光漏斗。

## 模型

### ① 有效新进（三层漏斗，只计参与者）

```
曝光 → 下载/进入 → 参与玩家 = 有效新进
expo × cvrDownload × cvrJoin
```

### ② 专区曝光池与稀释

```
专区周曝光池 = DAU × 人均专区曝光(3.2 次/日) × 7
稀释 dil = min(1, 专区周曝光池 / 在池玩法曝光需求)
```

在池玩法越多，单位曝光越薄，每个玩法的有效新进一起下降。

### ③ 14 天新鲜度衰减

```
第 1 周（上架当周）：平均权重 0.87
第 2 周（留存期）  ：平均权重 0.58
第 14 天退池后不再贡献新进
```

### ④ 同池倾轧（只在同时在池的玩法之间发生）

```
竞争强度 comp(g,o) = 同类型 ⊕ 标签 Jaccard ⊕ 受众结构余弦（打标数据优先，可人工覆盖）
压力 pressure = Σ comp(g,o) × 相对曝光份额
倾轧 damp = 1 / (1 + γ · pressure)
```

新批与上周批重叠的那 7 天，是同质化倾轧最严重的时间窗。

### ⑤ 覆盖缺口（太少 → 玩家玩不到想玩的）

```
每类玩法目标 = 该类型需求 × 6%（理想供给水平）
缺口惩罚 = λ · Σ demand_t · (1 − cover_t)²
```

### ⑥ 单玩法周期累计上限

```
cum(g) = Σ_周 该玩法当周有效新进          （14 天曝光期内的全部产出）
当周入账 eff = min(当周产出, capNew − cum_before)
cum ≥ capNew 后：曝光仍计入池需求与稀释，但不再产生新进，且不会被再次排入批次
```

- `capNew` 为「整个规划周期内的累计新进玩家数」，即该玩法可触达的新玩家总量或承接预算；留空 = 不设上限。
- 触顶的玩法会挤占槽位和曝光却不产出，因此模型在选批时会自动改用未触顶的玩法补位。
- 页面上同时给出每个玩法的「14 天自然产出」（无稀释、无倾轧）作为设置上限的参考基准。

### ⑦ 人群名单层（名单级重叠与获客可行性）

```
潜在人群名单 P(g) = lookalike(灰度参与玩家 ∪ 人工标注竞品玩法的玩家 → 画像原型)
                   在大盘近 3 个月 MAU 名单上按 0.40×分层亲和 + 0.44×标签余弦 + 0.16×大众人群 打分，
                   取分位阈值裁剪，名单规模 = 灰度参与人数 × 9（灰度只触达早期尝鲜者），限制在 MAU 的 1.5%~34%
重叠度：与目标周期活跃 = |P ∩ 周期活跃名单| / |P|
        与存量玩法   = |P ∩ 已上线留存名单并集| / |P|
        与同批玩法   = Jaccard(P_i, P_j)
获客上限 = |P ∩ 目标周期活跃| × 灰度参与率 × (1 − 0.45 × 竞品覆盖) × (1 − 0.35 × 同批最大重叠)
达成判定 = min(模型 14 天排期产出, 获客上限) ÷ 周期获客目标
```

- 竞品标注可同时包含已上线玩法（`L0x`）与待上架玩法（`g0x`），竞品玩家既是潜在人群的画像来源，也是转化时的分流来源。
- 名单规模为 0 或重叠为 0% 是有效结论：说明该玩法的人群画像与存量/同批几乎不重叠。

### ⑧ 目标函数与求解

```
max Σ_周 [ Σ 有效新进 × 品质权重 − λ · 覆盖缺口惩罚 ]
s.t. 本周批 + 上周批 ≤ 专区槽位，单周曝光需求 ≤ 专区曝光池，单玩法 cum ≤ capNew
```

对「每周上架数 X = 0…上限」逐一做**逐周滚动贪心**推演（本周批受上周批在池约束、候选池库存约束、单玩法周期上限约束），取整段累计效用最高的 X。

## 输入

| 输入 | 来源 |
|---|---|
| 首个上架日（自动取下一个周三）、规划周数、专区槽位、人均专区曝光 | 手动 |
| 近期 DAU、分层 DAU | 自动（示例为模拟快照） |
| 各类型玩法在分层的活跃渗透 | 自动 |
| 待上架玩法：名称、类型、品质、就绪度、单日曝光、`cvrDownload`、`cvrJoin`、**周期累计新进上限 `capNew`**、**周期获客目标 `goalNew`**、标签 | 人工录入（左栏可改/勾选/新增） |
| 灰度数据：灰度天数、灰度累计曝光、灰度累计参与（去重） | 灰度系统拉取（示例为模拟） |
| 人工标注竞品玩法（可含已上线 `L0x` 与待上架 `g0x`） | 人工标注 `AUDIENCE_INPUT[rivals]` |
| 大盘近 3 个月 MAU 名单、目标周期活跃名单、已上线玩法留存玩家名单 | 画像/名单服务（示例为模拟玩家宇宙 + 位图） |
| 玩法竞争关系 | 打标数据自动计算，`COMP_OVERRIDE` 可覆盖特例 |

## 输出

- **每周上架数 X**（主结论）与 X 周累计上架总数
- **每周三的批次组合**：本批玩法、同批在池的老批、曝光需求/池容、稀释、倾轧、本周有效新进、各玩法「累计 / 上限」
- **效用曲线**：X 从 0 到上限的「效用 / 累计新进 / 惩罚」三条线，标出峰值
- **归因**：每周再加 1 个会怎样、少 1 个会怎样（含边际产出、覆盖空档、上限触顶情况）
- **单玩法周期累计 vs 上限**：自然产出、实际累计、达成率、触顶批次、被上限截掉的产出
- **人群名单基数**：大盘 MAU / 目标周期活跃 / 已上线玩法留存名单规模与占比
- **待上架玩法潜在人群**：名单规模、占 MAU、与目标周期重叠、与存量留存重叠、纯新增、竞品覆盖、灰度参与人数、竞品标注
- **同批人群重叠矩阵**：首批玩法两两 Jaccard（判断是否在抢同一批人）
- **获客目标达成**：获客目标 / 名单口径可触达 / 名单上限产出 / 模型 14 天产出 / 达成率 / 卡点归因（人群不足、竞品分流、同批内耗、排期不足）
- **敏感度**：专区曝光池 ±30% 时最优节奏是否漂移
- **在池甘特**：每个玩法 14 天在专区的时间条，上架首周实心、留存第 2 周浅色

## 运行

```bash
# 直接打开
start index.html

# 或起本地服务
python -m http.server 8777
```

## 文件

```
index.html   页面结构
styles.css   样式（深色仪表盘）
data.js      模拟数据：DAU/分层/类型活跃/玩法池/打标/已上线玩法/灰度与竞品标注
model.js     模型：漏斗 → 曝光池稀释 → 新鲜度衰减 → 同池倾轧 → 覆盖缺口 → 按周滚动寻优
audience.js  名单层：玩家宇宙 → 潜在人群名单（位图）→ 重叠度 → 获客可行性
app.js       渲染与交互（Canvas 自绘曲线）
```

> 数据均为模拟数据。真实接入时，把 `data.js` 中 DAU、分层活跃、打标数据替换为数仓接口返回，玩法与漏斗参数保留人工录入；`audience.js` 的 `buildUniverse` 换成画像平台返回的名单（玩家 ID 集合 / 位图），重叠与可行性口径不变。
