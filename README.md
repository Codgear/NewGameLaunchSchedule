# NewGameLaunchSchedule

新玩法上架节奏预估 Demo：在「上太多相互倾轧、上太少玩家玩不到想玩的」之间，求解一段时间内**最优上架数量与玩法组合**。

纯静态页面，无构建、无依赖，`index.html` 直接打开即可运行。

## 模型

### 有效新进（三层漏斗，只计参与者）

```
曝光 → 下载/进入 → 参与玩家 = 有效新进
expo × cvrDownload × cvrJoin
```

### 约束与相互倾轧

| 机制 | 公式 | 含义 |
|---|---|---|
| 曝光位池 | `cap = DAU × 人均曝光位(3.2)`；`dilExpo = min(1, cap / Σexpo)` | 曝光需求超池 → 全体平均稀释 |
| 注意力时长池 | `dilLoad = min(1, 1 / Σload)` | 新玩法争夺有限的游玩时间 |
| 竞争矩阵 | 同类型 ⊕ 标签 Jaccard ⊕ 受众结构余弦（打标覆盖优先） | 同簇玩法直接争夺同一批玩家 |
| 倾轧折算 | `damp = 1 / (1 + γ · Σ comp(g,o)·relLoad(o))` | 同质化越严重，边际新进越低 |
| 覆盖缺口 | `Σ demand_t · (1 − cover_t)²`，目标 = 该类型需求的 20% | 上太少 → 玩家玩不到想玩的 |

### 目标函数

```
max  Σ 有效新进 × 品质权重 − λ · 覆盖缺口惩罚
s.t. Σ 曝光 ≤ 曝光位池,  Σ 注意力时长 ≤ 新内容时长池
```

在 `k = 1…N` 上做 **贪心构造 + 局部交换** 寻优，输出整条效用曲线并取峰值。

### 排期

按竞争强度做图着色分批（冲突对 ≥ 0.55 不同批），批间隔 ≥ 最小间隔，并标注是否超出排期窗口。

## 输入

- 目标上架日期、排期窗口天数、最小批间隔（手动）
- 近期 DAU 总量、新内容可争夺时长份额（手动，可替换为接口）
- 分层 DAU 与各类型玩法在分层的活跃渗透率（示例为模拟数据）
- 待上架玩法：名称、类型、品质、就绪度、曝光量、`cvrDownload`、`cvrJoin`、标签（左栏可编辑/勾选/新增）
- 玩法竞争关系：由标签 + 类型自动计算，`data.js` 中 `COMP_OVERRIDE` 可人工覆盖特例对

## 输出

- 建议上架数量（最优 k）
- 玩法组合：各玩法的有效新进、原始漏斗、贡献占比、倾轧损耗、所属批次
- 效用曲线（效用 / 新增 / 惩罚三条线，标记峰值）
- 定量归因：再多上一个会怎样、少上一个会怎样
- 敏感度：曝光位池 ±30% 时最优 k 的漂移
- 分批排期时间线

## 运行

```bash
# 直接打开
start index.html

# 或起本地服务
python -m http.server 8777
```

## 文件

```
index.html   页面结构
styles.css   样式（深色仪表盘）
data.js      模拟数据：DAU/分层/类型活跃/玩法池/打标
model.js     模型：漏斗 → 稀释 → 倾轧 → 覆盖 → 寻优 → 排期
app.js       渲染与交互（Canvas 自绘曲线）
```

> 数据均为模拟数据。真实接入时，把 `data.js` 中 DAU、分层活跃、打标数据替换为数仓接口返回，玩法与漏斗参数保留人工录入即可。
