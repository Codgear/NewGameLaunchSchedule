# NewGameLaunchSchedule

新玩法上架节奏预估 Demo：在「上太多相互倾轧、上太少玩家玩不到想玩的」之间，求解**每周三上新专区该上几个、上哪些玩法**。

纯静态页面，无构建、无依赖，`index.html` 直接打开即可运行。

## 业务场景

- 有一个「上新专区」，**每周三 10:00** 一次性同时上架 X 个玩法；
- 每批在专区**持续曝光 14 天**，超过 14 天退池；
- 因此任意时刻在池 = **本周批 + 上周批**（两批重叠 7 天），专区槽位同时被 2X 个玩法占用 → 单批上限 = ⌊槽位 / 2⌋。

## 模型

### ① 有效新进（三层漏斗，只计参与者）

```
曝光 → 下载/进入 → 参与玩家 = 有效新进
expo × cvrDownload × cvrJoin
```

### ② 专区曝光池与稀释

```
专区周曝光池 = DAU × 人均专区曝光(3.2 次/日) × 7
稀释 dil = min(1, 专区周曝光池 / 在池玩法曝光需求)
```

在池玩法越多，单位曝光越薄，每个玩法的有效新进一起下降。

### ③ 14 天新鲜度衰减

```
第 1 周（上架当周）：平均权重 0.87
第 2 周（留存期）  ：平均权重 0.58
第 14 天退池后不再贡献新进
```

### ④ 同池倾轧（只在同时在池的玩法之间发生）

```
竞争强度 comp(g,o) = 同类型 ⊕ 标签 Jaccard ⊕ 受众结构余弦（打标数据优先，可人工覆盖）
压力 pressure = Σ comp(g,o) × 相对曝光份额
倾轧 damp = 1 / (1 + γ · pressure)
```

新批与上周批重叠的那 7 天，是同质化倾轧最严重的时间窗。

### ⑤ 覆盖缺口（太少 → 玩家玩不到想玩的）

```
每类玩法目标 = 该类型需求 × 6%（理想供给水平）
缺口惩罚 = λ · Σ demand_t · (1 − cover_t)²
```

### ⑥ 目标函数与求解

```
max Σ_周 [ Σ 有效新进 × 品质权重 − λ · 覆盖缺口惩罚 ]
```

对「每周上架数 X = 0…上限」逐一做**逐周滚动贪心**推演（本周批受上周批在池约束、候选池库存约束），取整段累计效用最高的 X。

## 输入

| 输入 | 来源 |
|---|---|
| 首个上架日（自动取下一个周三）、规划周数、专区槽位、人均专区曝光 | 手动 |
| 近期 DAU、分层 DAU | 自动（示例为模拟快照） |
| 各类型玩法在分层的活跃渗透 | 自动 |
| 待上架玩法：名称、类型、品质、就绪度、单日曝光、`cvrDownload`、`cvrJoin`、标签 | 人工录入（左栏可改/勾选/新增） |
| 玩法竞争关系 | 打标数据自动计算，`COMP_OVERRIDE` 可覆盖特例 |

## 输出

- **每周上架数 X**（主结论）与 X 周累计上架总数
- **每周三的批次组合**：本批玩法、同批在池的老批、曝光需求/池容、稀释、倾轧、本周有效新进
- **效用曲线**：X 从 0 到上限的「效用 / 累计新进 / 惩罚」三条线，标出峰值
- **归因**：每周再加 1 个会怎样、少 1 个会怎样（含边际产出、覆盖空档）
- **敏感度**：专区曝光池 ±30% 时最优节奏是否漂移
- **在池甘特**：每个玩法 14 天在专区的时间条，上架首周实心、留存第 2 周浅色

## 运行

```bash
# 直接打开
start index.html

# 或起本地服务
python -m http.server 8777
```

## 文件

```
index.html   页面结构
styles.css   样式（深色仪表盘）
data.js      模拟数据：DAU/分层/类型活跃/玩法池/打标
model.js     模型：漏斗 → 曝光池稀释 → 新鲜度衰减 → 同池倾轧 → 覆盖缺口 → 按周滚动寻优
app.js       渲染与交互（Canvas 自绘曲线）
```

> 数据均为模拟数据。真实接入时，把 `data.js` 中 DAU、分层活跃、打标数据替换为数仓接口返回，玩法与漏斗参数保留人工录入即可。
